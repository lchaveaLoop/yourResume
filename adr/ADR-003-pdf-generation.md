# ADR-003: PDF 生成方案

## Status
Accepted

## Context
用户将简历网页预览导出为 PDF，要求：
1. 导出的 PDF 与网页预览高度一致（格式渲染一致性）
2. A4 幅面，标准简历尺寸
3. 用户本地生成，无需后端交互（快速响应）

## Decision

### 主方案：html2canvas + jsPDF（前端方案）

```
实施步骤：
1. 用户点击"导出 PDF"按钮
2. 定位到简历预览的根 DOM 容器（固定 A4 比例容器）
3. html2canvas 将 DOM 渲染为 Canvas（设置 scale: 2 保证清晰度）
4. jsPDF 将 Canvas 添加为 PDF 页面（A4: 210mm x 297mm）
5. 处理多页（如果内容超出一页，按区块拆分）
6. 触发浏览器下载
```

**选型理由**:
- 零后端依赖，用户本地即时生成，体验流畅
- 直接基于网页 DOM 渲染，保证预览与导出一致（同一份 HTML）
- 社区成熟，文档丰富

### 备选方案：后端 WeasyPrint

```
实施步骤：
1. 前端发送 HTML 字符串到后端
2. 后端使用 WeasyPrint 渲染 HTML → PDF
3. 返回 PDF 二进制流
4. 前端触发下载
```

**适用场景**: 前端方案在复杂模板下出现截断/分页问题时切换

---

## Consequences

### Positive
- 用户端即时生成，无网络延迟
- 预览与导出使用同一套 HTML/CSS，完全一致
- 方案简单，调试成本低
- 无需后端，MVP 阶段部署极简

### Negative
- html2canvas 对复杂 CSS（flex 嵌套、grid）可能出现渲染偏差
- 多栏布局需要手动处理分页逻辑
- 浏览器兼容性依赖 canvas 实现（主流浏览器均支持）
- 字体需要确保 Web Font 加载完成才能渲染准确

### Neutral
- 生成速度与页面复杂度正相关
- 移动端 canvas 性能略低，但简历页面通常不复杂

---

## Alternatives Considered

### 方案 B：jsPDF（纯代码生成）
- 优点：像素级控制，分页逻辑精确
- 缺点：需要重新用代码构建 PDF 布局，无法复用前端模板，工作量翻倍
- **未选**: 不符合"格式渲染一致性"核心原则

### 方案 C：浏览器原生 window.print()
- 优点：最简单，一行代码
- 缺点：样式控制粒度粗，页眉页脚难以去除，不同浏览器表现差异大
- **未选**: 无法满足高颜值导出需求

### 方案 D：后端 WeasyPrint
- 优点：渲染一致性好，支持复杂 CSS，分页逻辑成熟
- 缺点：需要后端部署，增加架构复杂度，PDF 生成需等待服务端响应
- **未选（MVP 阶段）**: 部署成本高于收益，待后续复杂度上升时引入
